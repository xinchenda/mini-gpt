## 1. 为什么租单卡

本机实验完成了数据质量、模型容量、上下文长度与恢复训练等对照，但最终模型只有约 507 万参数。其公开词预测任务的表现仍很弱。云端实验用于检验更大模型和更多训练数据是否带来可测的提升，并验证 CUDA 混合精度。

优先选择一张 RTX 4090D 24GB。候选小时价格为普通价 1.98 元、会员价 1.88 元；实际开机前再次核对。24GB 显存足够支持当前候选及梯度累积，单卡无需引入多机通信和分布式调度。没有购买会员、付费存储扩容或多卡服务。

## 2. 费用控制

| 阶段 | 费用上限 | 验收点 |
| --- | ---: | --- |
| 短跑测速 | 1 | loss 与梯度有限；保存和加载正常；测得 token/s |
| 正式训练 | 35 | 验证集持续记录；按计划结束或按时限保存退出 |
| 评测、导出与传输 | 8 | 固定任务报告、模型包、校验和、本机复载 |
| 余量 | 6 | 关机延迟及必要故障处理，不能自行追加训练 |

数据下载、词表训练和编码先在本机执行。代码和处理后的数据上传到同区文件存储，再创建实例。文件存储页面显示免费 20GB、付费 0GB；本轮远低于免费容量。GPU 运行前将数据复制到实例本地数据盘，以免网络盘读写影响训练。

实例开机即收费，训练程序退出不等于实例关机。`--max-seconds` 保存断点后退出；`scripts/budget_run.py` 限制单次阶段用时，并在命令成功或失败后调用平台关机命令。该脚本默认只打印计划，实际执行需要 `--execute`，并且仅允许在 AutoDL Linux 目录结构下运行。平台定时关机用于覆盖脚本启动前及守护程序异常的时段。每轮结束核对平台“已关机”状态与账单。

## 3. 数据准备

使用 HuggingFaceFW/FineWeb-Edu 官方数据集的固定版本与单个分片。来源、版本、原文件 SHA256、处理后文件 SHA256、各切分 token 数和文档数写入 `data/web_cloud/audit.json`。数据集许可为 ODC-BY 1.0，下载配方保留原始来源；正文不提交 Git。

~~~bash
python -m pip install -r requirements-cloud.txt
python -m minigpt_v2.prepare_web --output data/web_cloud --max-train-tokens 300000000
~~~

按文本内容散列分离训练、验证和测试，使相同文本归属同一角色；去除精确重复。BPE 词表只用训练角色的前 20,000 篇文档拟合，目标词表大小 16,384。每篇文档末尾插入 EOS，再写为小端 uint16 数据流。窗口允许越过 EOS。训练和验证使用内存映射读取；训练入口只检查测试文件指纹，不读取其 token 用于更新或选模。

这一处理不等同于近似去重或公开基准污染检查；报告必须保留该限制。使用新的词表后，token PPL 不与旧模型的 1,024 项词表直接比较。

## 4. 候选配置与测速

候选配置在 `configs/v2-cloud46m.json`：宽度 512、12 层、8 头、上下文 512，16,384 词表时为 46,480,384 参数。它是待验证候选，是否采用由短跑的速度、稳定性及费用决定。

正式训练 token 数按以下方式估算：

`训练秒数 = 目标 token 数 / 短跑实测 token/s`

`估算费用 = (训练秒数 + 评测和保存预留秒数) / 3600 × 实际小时价格`

训练日志中的平均吞吐包含检查点和固定验证开销。CUDA 在正式计时前同步，计时结束同步，避免将异步提交时间误当作完成时间。短跑沿用正式的上下文、批次、梯度累积和精度，额外记录显卡型号、PyTorch/CUDA 版本、显存峰值和有效目标 token 数。

以下是前期候选的测速命令，正式步数应在费用估算后锁定。`--stop-at` 在不改变整体学习率计划的情况下提前停止，之后可精确恢复：

~~~bash
python -m minigpt_v2.train \
  --manifest data/web_cloud/manifest.json \
  --config configs/v2-cloud46m.json \
  --output experiments/cloud/pilot \
  --steps 20000 --stop-at 100 \
  --batch-size 32 --accumulation 1 \
  --device cuda --precision bf16 --max-seconds 600
~~~

此命令本身不会关闭实例。实际在云端执行时，先配置平台定时关机，再由预算守护脚本包装执行。CPU/MPS 环境拒绝 `--precision bf16`，避免把未使用 CUDA 的运行误报成混合精度实验。

## 5. 训练、恢复与选模

AdamW、预热、余弦衰减、梯度裁剪、非有限值检查和原子检查点写入沿用本机路线。BF16 自动混合精度下，主参数与优化器状态保留 FP32；不使用 FP16 GradScaler。验证 loss 用 FP32 交叉熵汇总。

`--resume` 必须保持模型配置、数据指纹、精度、学习率、总步数和批次协议一致。短跑后若改变正式计划，应开新目录；同一计划的中断恢复保留优化器和采样状态。依据固定验证集选择最佳权重，不以公开测试集成绩选择训练步数。

## 2026-11-20 测速与正式方案

同一张 4090D 上顺序运行两组 100 步测速，训练批次 32、上下文 512、每次更新 16,384 个目标，BF16。测速包含固定验证和检查点写入开销，两组不同时占用 GPU。

| 候选 | 参数量 | 实测 token/s | 峰值分配显存 | 计划目标数 | 估算纯训练费 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 宽度 512、12 层 | 46,480,384 | 185,042.69 | 7,582,587,904 bytes | 1,000,013,824 | 2.82 元 |
| 宽度 768、12 层 | 98,032,128 | 99,260.49 | 10,145,661,952 bytes | 2,000,011,264 | 10.52 元 |

选用较大的 98M 配置及约 20 亿训练目标，按 1.3 倍时间保守估算为 13.68 元。该表是短跑外推，最终以实际日志与账单核验，尚不代表完整训练效果。编码语料有 300,001,097 个训练 token，随机窗口训练目标量约为该语料的 6.67 倍；这是重复采样量，不能写成 20 亿不同 token。

正式任务由 `scripts/cloud_continue.py` 接续所选 pilot 的优化器与采样状态，保持 122,071 步原计划，总目标 2,000,011,264。平台关机保护已改为北京时间 **2026-11-21 07:30**，设置页当时预计剩余费用 14.70 元。训练程序另有 7 小时限时保存，随后导出推理包、备份完整训练状态、尝试执行完整 LAMBADA 评测，最后请求关机；公开评测超时或失败会写入记录。若限时退出早于计划步数，状态中的 `completed_schedule` 为 false，不能宣称已完成全部训练。

云端状态文件位于 `/root/autodl-fs/cloud_status.json`，训练日志为 `cloud_formal.log`，最终推理包为 `cloud_model.zip`，完整恢复状态为 `cloud_training_state/`。这些结果需下载并复核后再发布。
