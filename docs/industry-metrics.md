# 公开基准与服务验收口径

## 模型质量

### 语言建模

本页相同词表的 v1/v2 对照指前序本机版本；云端 98M 使用新的 16,384 项词表，不能直接比较 token PPL。

交叉熵与困惑度用于衡量下一 token 预测。PPL 等于平均负对数似然的指数。不同词表、测试文本、上下文和窗口步幅会改变结果。因此本项目对 v1/v2 使用同一词表、同一文本、各自原生上下文（v1 为 64、v2 为 256）和 16 token 步幅，并记录每个目标的评分次数。

[Hugging Face 困惑度评估说明](https://huggingface.co/docs/transformers/en/perplexity)

### 公共任务

使用完整 LAMBADA OpenAI 5,153 题，任务是根据前文预测最后一个词。记录完整词贪心准确率及最后一个词的困惑度。任务的 prompt/target 划分与 EleutherAI 的 task specification 对齐。这里使用自实现 runner，提供数据 SHA256、上下文限制和评分口径。

[EleutherAI LAMBADA 任务定义](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/lm_eval/tasks/lambada/lambada_openai.yaml)

GPT-2 论文 Table 3 中 117M 配置的 LAMBADA 指标为 PPL 35.13、准确率 45.99%。该论文结果涉及不同训练规模、词表、上下文及输出约束，可作为能力差距的历史参考。项目实测结果与论文结果分别列示。上下文 64、1,024 词表及几百万参数的本机实验具有自己的资源约束。

本轮云端 98M 的实测准确率为 17.39%、最后词 PPL 206.79，与上述历史 GPT-2 数字仍有明显差距。这里没有用相同数据和官方评测运行 GPT-2，因此不是严格复现排名，也没有企业统一的“合格分数”。项目结项验收关注训练完成、产物可加载、证据可复核和费用受控；不将工程验收等同于模型能力达标。

[GPT-2 原始论文 Table 3 与 Section 3.3](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf)

## 系统指标

企业通常按具体业务约定时延、吞吐和可用性目标。vLLM 文档也指出不同工具的术语并非完全统一。本项目严格区分以下测量：

| 指标 | 测量边界 |
| --- | --- |
| 模型 token/s | 固定输入、固定输出长度，记录缓存开关、线程数与重复运行中位数 |
| HTTP 端到端 P50/P95 | 本机请求发出到完整 JSON 接收完成；20 次串行请求，先预热一次 |
| 成功与失败次数 | 同一批 HTTP 请求，失败单列 |
| 输出一致性 | 缓存与无缓存的贪心 token 完全一致 |
| 服务状态 | 健康接口真实返回 ready，参数越界返回 400，并发生成忙时返回 429 |

本项目内部的初步验收目标是 CPU 两线程、固定提示和 32 token 输出，20 次请求均成功且 P95 不高于 2 秒。这是项目自行定义的本机门槛。持续可用性、真实并发负载、TTFT 与流式逐 token 延迟需要另外的部署和测量，本次非流式服务只测完整响应时延。

[vLLM benchmark 指标说明](https://docs.vllm.ai/en/stable/benchmarking/cli/)

## 适合本数据的优化试验

27 本书长短差异较大。对照组按有效窗口数量采样，长书自然获得更多更新。候选方案将 70% 的长度权重与 30% 的有效书籍均匀权重混合，减轻长篇书籍占据训练批次的程度。

对照与候选均从 medium 的同一最佳 checkpoint 初始化，使用相同学习率、seed、5,000 步和每步目标数，仅改变训练采样混合比例。验证采样器保持不变。根据固定开发集分数决定保留哪个；新留出文本与公开基准在决策后评测。混合采样属于已知方法，这里检验的是适合本语料的配置，未主张算法首创。
